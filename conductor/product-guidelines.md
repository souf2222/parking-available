# Product Guidelines

## Tone and Voice
The application's tone and voice will be neutral and direct, purely informational, ensuring clarity and conciseness in all communications.

## Visual Aesthetics and Branding
The application will be designed for a mobile-only experience, adhering to the "iOS 26 UI Kit" guidelines. This will ensure a consistent and familiar user interface for mobile users.

## Handling Partial Availability
For days with partial availability (e.g., "available from 1 PM"), a simple text input field will be provided, allowing me to write custom messages to specify the exact availability.

## Notification Mechanism
Notifications about changes in parking availability will be handled manually; the neighbor will receive updates by visiting the web application. There will be no active push, email, or SMS notifications.

## Data Retention
The application will maintain a rolling 30-day history of past parking availabilities, allowing for a short-term review of historical data while keeping the data footprint manageable.
